# OCR 做题定位：使用与实现说明

## 如何使用

1. 进入 **设置 → 做题模式**，选好做题专用的视觉模型配置。
2. 关闭“固定选项位置”，打开“**OCR 定位选项**”。固定坐标优先级最高，打开固定坐标时不会调用 OCR 定位。
3. 第一次保留“**仅预览，不点击**”。使用做题快捷键或“截图并分析一次”，检查做题页面中的彩色分组框和红点。
4. 分组和红点正确后，关闭“仅预览，不点击”。按钮只执行一轮，做题快捷键开始循环，再按一次停止；界面也提供停止按钮。
5. “显示 OCR 分组图”控制自动点击模式的截图预览；仅预览模式始终显示截图。

OCR 定位默认关闭，预览默认开启。四边过滤继续在“本地 OCR”面板中配置，默认各 100 个输入图片像素。可以将某边改为 0。截图裁剪后的图片是 OCR 坐标的原图，过滤本身不改变坐标。

## 这次实现的行为

- 同一张截图交给本地 OCR 和做题视觉模型。模型返回题干、答案、选项文字及文字框 ID，程序校验后从原始框中取点，不使用模型生成的 OCR 点击坐标。
- 一道题可以有 1–26 个实际选项，兼容两项、三项、单选、多选和顺序选择。多行选项保留每行原始框，AI 用 `clickRegionId` 指定点击哪个框，程序取该框中心。
- 全部目标（包括下一步）通过校验后才开始点击；答案按返回数组顺序执行，点击之间至少等待 500 ms；一轮结束后再等待 3000 ms。
- OCR 策略会在点击前复查题干及尚未点击的区域。题目滚动、跳转、显示器变化或截图过旧时丢弃旧计划，提示并等待 3 秒后重新截图、OCR 和 AI 分析；支持单次和循环任务。
- 再次识别出同一题时进入补充分析，确认当前已选项及下一步；同题最多补救 3 次。第三次操作后等待 3 秒再确认，仍为同题或无法确认新题才停止。
- 固定坐标模式和旧 AI 坐标模式保留。它们不额外做 OCR，也不启用 OCR 的局部画面复查。
- 性格模式保持独立；关闭不发送人格/历史。人格改变会清空旧会话；改变做题配置会停止当前任务；停止再开始不清空人格会话。设置中“开始新测评 / 清空记忆”可以主动建立新会话。
- 同题选项换序时按选项内容重新映射历史答案，不复用旧字母或坐标；同文选项有歧义时交由本次分析。
- 设置页往返通过主进程快照恢复本轮结果、原始 AI 输出及状态。图片不写入 localStorage，不保存进性格记忆。

## 边界与提示

当前自动定位要求点击 OCR 文字可选中。AI 根据截图判断选项归属，不再用固定栏数、缩进和行距限制选项。只有图片、只能点击独立圆圈/复选框或题目被截断时仍可能无法定位；可使用已有固定坐标功能。取消多列硬限制不等于已经验证所有复杂版面。

普通“下一步/下一题/继续”可以自动点击；识别为提交/交卷时要求人工处理，不自动提交整卷。若选中后按钮颜色、布局变化触发画面复查，会自动重新识别。已执行部分答案时，AI 必须基于新截图确认 `selectedAnswers`，程序跳过已选前缀，只执行剩余步骤。无法确认选中状态、答案冲突或格式错误仍停止，不盲目重放。

“已执行点击”表示系统点击调用完成，不表示已验证网页选中或提交成功。测试和界面均区分预览、计划、部分执行和执行完成。

Windows 系统点击仍使用原 user32 实现，增加了任务互斥、超时和异常释放鼠标处理。当前不支持负屏幕坐标，混合 DPI 多显示器仍需要单独实测；macOS 可以预览，但不能自动点击。

记忆最多 500 条，不保存截图；历史超过 12 万字符会在新一轮开始前提示，而不是自动截断。这个阈值是本地保护，不代表所有模型都支持相应上下文长度，服务端仍可能报告上下文不足。

业务入口：`src/main/assessment.ts`，负责组装服务、IPC 和设置变更通知。

| `ocr-regions.ts` | 校验图片尺寸与文字框边界、生成稳定 ID，不做预分组 |

| `prompt-builder.ts` | 三种定位策略的提示词、人格及历史消息 |
| `response-validator.ts` | 严格 JSON、重复键、答案、引用存在性/唯一性及点击框归属校验 |
| `target-resolver.ts` | 固定/OCR/旧 AI 坐标策略与完整点击计划 |
| `coordinate-mapper.ts` | 图片、裁剪偏移与屏幕坐标换算 |
| `click-executor.ts` | 顺序点击、间隔、取消和执行计数 |
| `page-guard.ts` | 同一截图区域复查，变化时抛出可恢复事件 |
| `recovery.ts` | 页面变化/不确定状态事件、临时执行记录与跳过已选前缀 |
| `retry-session.ts` | 当前题身份、共用 3 次恢复预算与补救记忆去重 |
| `memory-service.ts` | 人格会话版本、文本记录和换序答案匹配 |

共享类型在 `src/shared/assessment.ts`；前端状态在 `lib/store/assessment.ts`，彩色分组预览在 `assessment/OcrDebugPanel.tsx`。

## OCR 协议 v3：AI 选择文字框

同一张截图的 OCR 结果在原有边缘过滤后，经过 `filterAssessmentOcrRegions()` 原样送出。函数目前不按内容、置信度、数字、区域或关键词删除任何框，不修改 ID、文字和坐标。预留函数只在自动做题准备输入时调用，不影响本地 OCR 独立测试。

输入只有 `ocr.regions`（id、text、score、box）及诊断元数据，不再包含 `q001` 题块或本地候选分组。侧栏、数字选项和独立字母都交给 AI 判断。程序不再要求 AI 的引用落在本地划定的题块内。

```json
{
  "schemaVersion": 3,
  "captureId": "本次截图 ID",
  "status": "ok",
  "question": "完整题干",
  "questionRegionIds": ["r005"],
  "answers": ["A"],
  "options": {
    "A": {"text": "105", "regionIds": ["r008", "r009"], "clickRegionId": "r009"},
    "B": {"text": "89", "regionIds": ["r015"], "clickRegionId": "r015"}
  },
  "next": {"required": true, "kind": "next", "clickRegionId": "r028"}
}
```

- `questionRegionIds` 标记题干/材料，用于原有点击前页面变化检查；它不是本地题块编号。
- `regionIds` 按 AI 判断的阅读顺序列出选项各行；选项的最终文字由程序从引用的 OCR 原文拼接，移除选项标签。AI 返回的 text 若不同只提示，不阻断、不重新请求 AI。
- `clickRegionId` 必须属于该选项；下一步也只引用一个真实 OCR 框。中心坐标由程序计算，不接收模型坐标。不能凭字母框置信度偏低就否定它。
- 检查所有引用存在且不重复，题干/选项/下一步不能交叉引用；无效答案或目标在任何点击前被拒绝。
- 下一步文字识别为“下—题”不再被本地白名单拒绝，由 AI 结合截图判断按钮用途。明确提交/交卷仍停止。
- AI 可以返回 `status: "uncertain"` 和 `reason` 停止。不接受旧 v2 响应；下一次请求自动使用 v3 提示词，不要手工回放旧协议。
- 原图坐标和截图/屏幕变换不变。OCR 失败或引用校验失败时停止，不回退到模型估计坐标。画面变化则走下述自动恢复流程。
- 预览在分析前显示全部 OCR 框，分析后按 AI 引用显示题干、选项和下一步。

本次仅改变启用“OCR 定位选项”后的流程，固定坐标和关闭 OCR 时的旧模式设置保持兼容。

## 请求前缀与缓存

做题请求按以下顺序发送，OCR、固定坐标和模型坐标三种策略共用这一结构：

1. 系统提示词：本次性格（仅性格模式）、策略规则和固定的条件式补充分析说明。有无 `recovery` 不再改变系统提示词；只有本轮 JSON 含 `recovery` 时才要求 `selectedAnswers`。
2. 用户第一段文本：`assessmentHistory:` 加本次历史原文，仅性格模式发送。空会话也保留这个固定开头，旧记录保持原样，新记录追加在末尾。
3. 用户下一段文本：本轮 JSON，包括随机 `captureId`、图片尺寸、OCR（如有）和 `recovery`（如有）。
4. 用户最后一段：当前截图，不累积旧截图。

历史是参考资料，不代表当前页面已经选中哪些选项。普通模式不发送性格或历史；切换性格模式、修改性格和清空会话仍按原有规则管理记忆。模型响应协议及点击校验保持不变。

此顺序让固定规则和历史形成连续公共前缀，避免随机编号和当前 OCR 提前打断可复用内容。缓存是否命中仍取决于服务端落盘、保留时间和具体模型策略，不保证首轮或下一轮立即命中。应以 API 返回的缓存命中/未命中 Token 和实际费用验证，不以本地前缀测试代替真实命中率。

## 画面变化自动恢复

检测到画面变化、截图尺寸变化或原截图超过 60 秒时，界面显示“将在 3 秒后重新截屏识别（重试 N/3）”，不显示错误、不关闭循环，也不释放任务锁。单次按钮任务同样会恢复直到完成。每次使用新截图、新 captureId、新 OCR 和新 AI 响应，旧计划不会继续执行；画面变化与同题未跳转共用当前题的 3 次补充分析机会，不无限重试；可通过停止按钮或快捷键取消。

- 恢复提示和记录只属于当前运行，不是性格记忆，普通模式也需要它来避免重复点击。结束/停止后不持久化。
- `recovery` 输入包含前一次题干、选项文字、目标答案和已执行答案；不包含旧坐标或旧文字框编号。
- 重新分析的 `ok` 响应额外要求 `selectedAnswers`，如已选 B 则返回 `["B"]`；没有选中或已换到新题则返回 `[]`。`answers` 仍是完整答案顺序。
- 已选数组须无重复、属于目标答案且为其有序前缀；程序跳过这些步骤，仅生成剩余选项和下一步计划。当前图像状态由 AI 确认，不能只凭过去点击过就认定已经选中。
- 成功的部分点击不会提前写入性格记忆；整轮完成后才写入。
- 页面变化、同题未跳转及 AI 明确返回 uncertain 可消耗恢复预算重新分析。OCR/网络/JSON 格式错误仍显示具体错误；选中状态无法确认时不点击，也不会无限重试。
- 结果中的 `confirmedSelectedAnswers` 为本次重新识别确认并跳过的答案，`executedSteps` 只统计当前新计划的点击次数。

自动恢复验证：79/79 自动化测试通过，覆盖首步前/部分选项后/下一步前恢复、连续变化后停止、普通错误不重试、已选状态校验与普通模式记忆隔离。构建及修改范围 ESLint 检查通过。真实本地 OCR 配合模拟 AI 和 Chromium 测试页，换题后重新分析以及按钮变色后跳过已选项的流程均通过；未验证真实模型及 Windows 物理点击全链路。

## 选项文字差异不阻断

AI 返回的 `options.text` 与引用文字有标点、断行或改写差异时，服务端使用对应 `regionIds` 的 OCR 原文作为展示和记忆的选项文字。`raw` 保留原始 AI 输出，结果 `notices` 及界面显示“选项 B 的文字已采用 OCR 原文，继续执行”。差异不会抛出异常、触发重新识别或增加 AI 调用；正确的点击框照常解析执行。文字框不存在、重复引用、点击框不属于选项、空 OCR 正文等仍会拦截。

回归测试使用用户日志中的 B 选项与冒号/分号差异，确认只请求一次 AI、完成选项及下一步点击、记忆采用 OCR 原文。自动化测试 81/81 通过。

## 同题未跳转：最多三次补救

循环做题在正常操作完成后等待 3 秒，再用新截图和新 OCR 分析。请求会带上一轮操作记录，要求 AI 返回当前确认已选的 `selectedAnswers`，特别检查是否遗漏下一步。只执行未选的答案与下一步，不整组重放。

首次作答不占重试次数；同题的补充分析依次为 1/3、2/3、3/3。“画面变化”和“同题未跳转”共用该次数；uncertain 只分析不点击，同样计次。第 3 次操作后还会等待并做一次确认分析，若已经新题则清零并继续，若仍同题或无法确认新题，则停止，绝不执行第 4 次补救点击。

题目身份以当前 OCR 题干/材料、选项内容及可识别的题号为依据，排除选项字母换序、坐标、换行和常见标点差异；保留小数点和数学运算符。OCR 题号缺失时不会仅因缺失而清零；实际识别文字变化、题号误识别仍可能影响判断。对无法区分的重复题采取有限补救，不保证能辨别所有网站的页面进度。

补救沿用当前题的记忆提交标记，不重复新增记录；新题才重置。暂时的执行记录和次数不落盘，与性格开关无关。

本次 86 项自动化测试通过，覆盖遗漏下一步、三次后最终确认、最后一次补救成功进入新题、混合恢复预算、不确定状态不点击、标点/选项换序身份及重复记忆。真实 OCR 的集成诊断使用模拟 AI 和 Chromium 输入，不代表已验证真实模型或实际网站。
