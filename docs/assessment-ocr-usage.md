# OCR 做题定位：使用与实现说明

## 如何使用

1. 进入 **设置 → 做题模式**，选好做题专用的视觉模型配置。
2. 关闭“固定选项位置”，打开“**OCR 定位选项**”。固定坐标优先级最高，打开固定坐标时不会调用 OCR 定位。
3. 第一次保留“**仅预览，不点击**”。使用做题快捷键或“截图并分析一次”，检查做题页面中的彩色分组框和红点。
4. 分组和红点正确后，关闭“仅预览，不点击”。按钮只执行一轮，做题快捷键开始循环，再按一次停止；界面也提供停止按钮。
5. “显示 OCR 分组图”控制自动点击模式的截图预览；仅预览模式始终显示截图。

OCR 定位默认关闭，预览默认开启。四边过滤继续在“本地 OCR”面板中配置，默认各 100 个输入图片像素。可以将某边改为 0。截图裁剪后的图片是 OCR 坐标的原图，过滤本身不改变坐标。

## 这次实现的行为

- 同一张截图交给本地 OCR 和做题视觉模型。模型返回题干、答案、选项文字及文字框 ID，程序校验后从原始框中取点，不使用模型生成的 OCR 点击坐标。
- 一道题可以有 1–26 个实际选项，兼容两项、三项、单选、多选和顺序选择。多行选项保留每行原始框，点击第一行正文中心。
- 全部目标（包括下一步）通过校验后才开始点击；答案按返回数组顺序执行，点击之间至少等待 500 ms；一轮结束后再等待 3000 ms。
- OCR 策略会在点击前复查题干及尚未点击的区域。题目滚动、跳转、显示器变化或截图过旧时停止旧计划，不自动重复点击。
- 再次识别出相同题目和选项时暂停，避免多选被重复点击取消；无法区分真实重复题与页面未切换时也会暂停。它是循环保护，不是性格记忆。
- 固定坐标模式和旧 AI 坐标模式保留。它们不额外做 OCR，也不启用 OCR 的局部画面复查。
- 性格模式保持独立；关闭不发送人格/历史。人格改变会清空旧会话；改变做题配置会停止当前任务；停止再开始不清空人格会话。设置中“开始新测评 / 清空记忆”可以主动建立新会话。
- 同题选项换序时按选项内容重新映射历史答案，不复用旧字母或坐标；同文选项有歧义时交由本次分析。
- 设置页往返通过主进程快照恢复本轮结果、原始 AI 输出及状态。图片不写入 localStorage，不保存进性格记忆。

## 边界与提示

当前自动定位支持单列文字选项、点击文字可选中的页面。只能点圆圈/复选框、复杂多列、图片选项、被截断的题目等尚未加入专用控件定位，定位不明确会停止；可使用已有固定坐标功能。

普通“下一步/下一题/继续”可以自动点击；识别为提交/交卷时要求人工处理，不自动提交整卷。若选中后按钮颜色、布局变化触发画面复查，当前会保守地停止，不猜测继续。

“已执行点击”表示系统点击调用完成，不表示已验证网页选中或提交成功。测试和界面均区分预览、计划、部分执行和执行完成。

Windows 系统点击仍使用原 user32 实现，增加了任务互斥、超时和异常释放鼠标处理。当前不支持负屏幕坐标，混合 DPI 多显示器仍需要单独实测；macOS 可以预览，但不能自动点击。

记忆最多 500 条，不保存截图；历史超过 12 万字符会在新一轮开始前提示，而不是自动截断。这个阈值是本地保护，不代表所有模型都支持相应上下文长度，服务端仍可能报告上下文不足。

## 代码分工

业务入口：`src/main/assessment.ts`，负责组装服务、IPC 和设置变更通知。

| 文件（相对 `src/main/assessment/`） | 职责 |
| --- | --- |
| `controller.ts` | 唯一任务锁、单次/循环、停止、状态快照 |
| `runner.ts` | 一轮阶段编排，不直接操作鼠标 |
| `ocr-layout-analyzer.ts` | 文字框编号、题目块、独立标签、续行分组 |
| `grouping-config.ts` | 归组参数 |
| `prompt-builder.ts` | 三种定位策略的提示词、人格及历史消息 |
| `response-validator.ts` | 严格 JSON、重复键、答案/文字框/几何关联校验 |
| `target-resolver.ts` | 固定/OCR/旧 AI 坐标策略与完整点击计划 |
| `coordinate-mapper.ts` | 图片、裁剪偏移与屏幕坐标换算 |
| `click-executor.ts` | 顺序点击、间隔、取消和执行计数 |
| `page-guard.ts` | 同一截图区域复查，不推断选中成功 |
| `memory-service.ts` | 人格会话版本、文本记录和换序答案匹配 |

共享类型在 `src/shared/assessment.ts`；前端状态在 `lib/store/assessment.ts`，彩色分组预览在 `assessment/OcrDebugPanel.tsx`。

实际样本校准后，续行间隙上限采用文字框高度的 **0.9 倍**。理由是 Windows 150% 缩放的测试页中，OCR 字形框高约 27 像素、同行段落行距约 21 像素，设计初值 0.6 会错误拆开。该启发式仍不能代替截图确认。

对于明显偏小的孤立数字/圆圈识别噪声，仅从题目候选行中排除，原始调试文字框保留。用户提供的 SQL 日志中，小图标误识别出的“3”因此不会打断第二个选项的两行。

## 验证命令

```powershell
node --test tests/assessment-options.test.cjs tests/ocr-filter.test.mjs tests/assessment-ocr.test.mjs
npm run build
```

本地集成诊断使用真实本地 OCR 和隐藏的 Chromium 测试页，AI 回复为可控桩。不会调用客户配置的 AI，不会移动系统鼠标，不打开实际测评页面。

```powershell
$report = Join-Path $env:TEMP 'assessment-ocr-report.json'
Start-Process '.\node_modules\electron\dist\electron.exe' `
  -ArgumentList '.', "--assessment-self-test=$report" -WindowStyle Hidden -Wait
Get-Content $report
```

打包程序也支持相同参数：

```powershell
$report = Join-Path $env:TEMP 'assessment-ocr-packaged-report.json'
Start-Process '.\dist\win-unpacked\截屏解题助手.exe' `
  -ArgumentList "--assessment-self-test=$report" -WindowStyle Hidden -Wait
Get-Content $report
```

报告 `passed: true` 表示集成诊断通过，`packaged: true` 表示运行的是打包程序。覆盖真实 OCR、多行归组、预览零点击/零记忆、测试页 B→A→下一步的输入命中、500ms 间隔、分析期间换题拦截。输入使用 `webContents.sendInputEvent`，不能据此宣称已验证 Windows 物理鼠标注入或实际网站成功率。

设计中的圆圈控件定位、选中状态确认、复杂多列等仍属后续扩展。真实模型对 v2 协议的遵循情况及实际网站页面，需要通过预览模式继续验收。
