# 编码面试助手 / 语音面试助手 / 在线考试助手 / 笔试助手

> 面试和笔试的隐身 AI 助手：屏幕上的题，截图就解；面试官的问题，说完就有提示。

> 本仓库基于 [ooboqoo/interview-coder-cn](https://github.com/ooboqoo/interview-coder-cn) 持续开发，支持截图、对话和做题三种模式。下载见[本仓库 Releases](https://github.com/12owo21/interview-coder/releases)，本次更新见 [1.2.0 Release 说明](RELEASE_NOTES.md)。

## 三种模式

| 模式     | 主要用途                         | 使用方式                           | 模型要求                                    |
| -------- | -------------------------------- | ---------------------------------- | ------------------------------------------- |
| 做题模式 | 识别题目和选项，按答案点击       | 单次分析或快捷键启动循环           | 支持图片输入的视觉模型，即使开启 OCR 也需要 |
| 截图模式 | 分析算法题、文字题、图形题等     | 截图、追加截图、追问，流式显示解答 | 支持图片输入的视觉模型                      |
| 对话模式 | 将语音内容转成文字并生成回答提示 | 自动或手动触发提示                 | 文本模型；另外需要百炼语音识别 Key          |

三种模式可以分别选择 AI 配置。截图模式与对话模式支持各自的提示词场景和资料库；做题模式使用专门的答题规则及可选的个人性格配置。

保留窗口置顶、透明度调整、鼠标穿透、快捷键等桌面功能。截图模式还支持代码自动复制或保存，相关功能需在设置中开启。

## 为什么选它

- **三种模式一体**：截图分析、语音提示和自动做题在同一个窗口里，各自选用 AI 配置；截图与对话模式可分别配置提示词场景
- **适配国内生态**：中文界面，支持硅基流动、DeepSeek 等兼容 OpenAI API 的平台；做题和截图模式需选择视觉模型，语音识别使用阿里云百炼
- **屏幕共享内容保护**：使用系统提供的窗口内容保护机制，效果取决于操作系统与会议软件，请在当前环境中测试
- **桌面操作便捷**：窗口置顶半透明，支持鼠标穿透；截图与对话模式还可使用悬浮工具条操作
- **开源、自带 Key、没有订阅费**：直接调用你自己的 AI 平台，花多少钱看得见
- **追求快**：可按模型支持情况关闭思考；对话模式在一句话结束后生成提示，对方继续说话时会更新尚未完成的提示

## 适用场景

| 场景                    | 用法                                                                             |
| ----------------------- | -------------------------------------------------------------------------------- |
| 算法笔试 / 在线编程题   | 截图模式「解算法题」：给出思路和完整代码，题目长就追加截图，代码可自动复制或保存 |
| 技术面试（视频 / 语音） | 对话模式「技术面试」；面试官共享编程题时，切到截图模式「解算法题」               |
| HR 面 / 主管面          | 对话模式「行为面试」：按 STAR 给出经历类问题的回答要点                           |
| 英文面试                | 对话模式「英文面试」：给出英文回答要点，并用中文说明对方问的是什么               |
| 英语机试                | 截图模式「英语考试」，听力题可以配合语音转录                                     |
| 能力测评 / 行测         | 截图模式「能力测评」：逻辑、图形、数字推理，直接给出选项和关键依据               |
| 其他在线考试            | 截图模式「通用问答」：单选、多选、解答等通用题型                                 |
| 选择题 / 性格测评       | 做题模式：按题目与选项生成答案并点击，可开启性格配置、测评记忆和选项评分         |
| 以上都不是              | 在设置里新增自定义场景，写自己的提示词                                           |

截图模式的编程题默认用 TypeScript 作答，题目指定了语言时按题目要求。

## 快速开始

### 1. 下载安装

到[本仓库 Releases](https://github.com/12owo21/interview-coder/releases) 下载对应平台的安装包。Windows 使用 `*-setup.exe`；macOS 如有提供，以发布页标注的架构为准。做题模式的自动点击和鼠标移动目前仅支持 Windows。

安装和首次打开的通用操作可参考[上游 Wiki 教程](https://github.com/ooboqoo/interview-coder-cn/wiki/%E7%9B%B4%E6%8E%A5%E4%B8%8B%E8%BD%BD%E5%AE%89%E8%A3%85%E5%8C%85%E4%BD%BF%E7%94%A8)，本仓库新增功能以本文说明为准。

### 2. 配置 AI

首次打开会提示填写 `API Base URL` 和 `API Key`。任何兼容 OpenAI API 的平台都可以，如国内的 [硅基流动](https://cloud.siliconflow.cn/i/SG8C0772)、DeepSeek，国外的 [OpenRouter](https://openrouter.ai/)，或 OpenAI 官方（只填 `API Key` 即可）。

在「设置 → AI 模型」里可以保存多套配置，通过「用于」按钮分配给做题、截图、对话模式，也可以到各模式设置中选用。同一个配置可供多种模式共用：

- 截图模式和做题模式会发送截图，需要**能识图的模型**；做题模式即使开启 OCR，也仍需要图片输入能力
- 对话模式只发文字，建议选一个**打开「关闭思考」的快模型**，出提示更快

> 部分平台或网关除了 API Key 还要求额外的请求头（如 Azure 的 `api-key`、Cloudflare AI Gateway 的 `cf-aig-authorization`），可以在配置的「高级 → 自定义请求头」里每行填一个 `名称: 值`。

### 3. 开始使用

- **截图模式**：按 `⌥ Enter`（Windows 为 `Ctrl+Enter`）截图解题
- **对话模式**：
  1. 在[百炼平台控制台](https://help.aliyun.com/zh/model-studio/get-api-key)创建 API Key，填到「设置 → 语音」
  2. 点窗口顶部的「对话」切换过去（或按 `⌥⇧M` / `Ctrl+Shift+M`）
  3. 按 `⌥ T`（Windows 为 `Ctrl+T`）开始监听，对方说完一句话，右侧就会出提示

语音识别使用阿里云百炼的 Fun-ASR 实时模型，计费与额度以百炼官网为准。

### 4. 首次运行做题模式

1. 在「设置 → 做题模式」选择 AI 配置，开启「OCR 定位选项」，关闭「固定选项位置」。
2. 开启「仅预览，不点击」，将题目显示在目标屏幕上，切换到「做题」页面，点击「截图并分析一次」。
3. 检查 OCR 分组图、点击红点、AI 输入与输出。预览只分析，不执行点击，也不写入测评记忆。
4. 确认定位符合预期后，关闭「仅预览，不点击」。此时「截图并分析一次」会执行一轮分析和点击。
5. 按 `Ctrl+Q` 开始循环，再按一次停止；也可使用页面上的「停止做题」或 `Ctrl+.` 停止。

OCR 预览模式下，做题快捷键也只分析一次。循环中遇到无法继续处理的错误或需要人工提交的页面会停止。

## 做题模式使用说明

### 选项如何定位

| 定位方式 | 设置方法                                           | 点击位置                                         |
| -------- | -------------------------------------------------- | ------------------------------------------------ |
| 固定坐标 | 开启「固定选项位置」，填写各选项与可选的下一步坐标 | 使用手动输入的屏幕坐标，优先于 OCR               |
| OCR 定位 | 关闭固定坐标，开启「OCR 定位选项」                 | AI 返回选项对应的文字框编号，程序点击 OCR 框中心 |
| 模型坐标 | 同时关闭固定坐标与 OCR 定位                        | AI 返回截图中的矩形，程序换算为屏幕坐标          |

固定坐标适合选项布局稳定的页面，位置变化后需要重新配置。坐标使用屏幕物理像素，不能直接填写裁剪截图中的局部坐标。

### 本地 OCR 与文字框过滤

本地 OCR 使用 PaddleOCR 模型，通过 `ppu-paddle-ocr` 和 ONNX Runtime 在本机执行。模型随应用打包，首次识别时加载，空闲一段时间后释放模型内存。设置中的「本地 OCR」支持选择 PNG 测试。

「OCR 边缘过滤」按输入图片四边的像素距离排除外围文字，默认每边 100 像素，某边设为 0 表示不排除该边。判断依据是**文字框中心是否位于保留区域内**，保留框的坐标不变；题目靠近边缘时，应减小对应值。

分组图刚出现时展示 OCR 识别并保留的文字框，AI 返回后只绘制它引用的题目、选项和按钮框，因此会看到文字框变少。这是展示范围的变化，并不代表又调用了一次 AI 做过滤。

**正常一轮由一次 AI 请求同时完成答题与文字框选择。** 输出校验失败、页面变化或同题恢复等情况可能产生额外请求，所以并非所有轮次都只有一次调用。

### 性格测评与选项评分

- **性格测评模式**：按「个人性格配置」回答，并记录当前测评的题目、选项和答案，用于后续题目保持一致。
- **最符合／最不符合模式**：使用独立评分记忆，AI 为新选项打 0～10000 分，程序先点击最高分，再点击最低分；已记录选项按内容复用评分。开启后普通逐题记忆暂不使用。
- **判断选项是否已选择**：默认开启，补充分析时跳过已确认选中的选项。关闭后可能重复点击，部分页面会因此取消原选择。

测评记忆仅保留在本次应用运行中，重启后不保留。开始另一份测评时，点击「开始新测评 / 清空记忆」。

### 答题后随机停放鼠标

在「设置 → 做题模式」中：

1. 点击「添加区域」。
2. 输入矩形的**左上角 X、Y** 和**右下角 X、Y**。
3. 根据需要添加多个矩形，点击「保存区域」。删除区域后也需要保存。
4. 开启「答题后随机停放鼠标」。可以先用「测试停放（不点击）」检查效果。

每轮选项及下一步的点击全部完成后，程序等概率选取一个区域，再将鼠标移到区域内部的随机点，停放时不点击。此设置直接输入坐标，**不依赖截图框选功能**。

坐标需为非负整数，右下角必须位于左上角的右下方，所有区域都必须在本轮做题的屏幕内。例如，原点为 `(0, 0)` 的 1920×1080 屏幕，其最大坐标为 `(1919, 1079)`。请选取页面空白区域，避免停放后遮挡题目。

随机停放默认关闭；删除全部区域并保存后会关闭停放。旧版框选停放区域不会自动转换，升级后需要重新输入坐标并保存。

### 鼠标直线移动

「鼠标直线移动」与随机停放是两个独立开关，**默认均关闭**。

开启直线移动后，每次点击前以及停放时，鼠标都会从当前位置沿直线缓入缓出移动，因此相邻两次点击之间也有移动轨迹；关闭时直接定位。单段移动约 180～600ms，实际操作还包含系统辅助进程的启动时间。

移动算法已封装为独立接口与类，开发说明见 [做题模式鼠标控制](docs/assessment-mouse-controls.md)。

### 查看 AI 原始输入与输出

做题页面按 **OCR 识别结果 → AI 原始输入 → AI 原始输出** 的顺序展示信息；OCR 图是否显示由预览及「显示 OCR 分组图」设置决定。

- **AI 原始输入**：展示请求前实际使用的系统提示词和消息，包括本轮适用的 OCR 文字、性格配置、测评记忆及纠错信息；随请求发送的截图可以展开查看。
- **AI 原始输出**：有效 JSON 默认按缩进结构化展示，可点击「查看原文」，再点击「结构化 JSON」切回。流式输出未完成或不是有效 JSON 时保留原文。
- 发生纠错请求时，输入区域会更新为本次请求内容并显示请求次数。该区域不展示 API Key 或请求头。

### 当前限制

- 自动鼠标操作仅支持 Windows，目前不支持主屏左侧或上方显示器上的负坐标。多屏和混合缩放环境需先预览核对位置。
- 模型判断和 OCR 可能出错；鼠标点击执行完成不等于网页已经接受答案。明确的提交、交卷操作会停下来交由用户处理。
- 截图区域框选目前存在已知可用性问题，本版本未修复；可先使用整屏截图。鼠标停放区域使用手动坐标配置，不受该问题影响。

## 对话模式怎么出提示

- **自动**（默认）：对方说完一句话立刻出提示。如果对方其实还没说完，这条提示会先撤回，等说完后重写到同一张卡里；「好的」「嗯」这类太短的句子不会触发
- **手动**：只在按「出提示」快捷键时出
- 两种方式下都可以随时按「出提示」立即出，不等对方说完；没有新内容时再按一次，会把上一条换个说法重出
- 左边是对方说的话，右边是提示；鼠标移到某条提示上，左边会高亮它对应的问题
- 对话模式采集的是系统音频，线上面试时就是会议里对方的声音，触发内容取决于系统音频实际包含哪些声音。「说完判定」的停顿时长和触发字数可以在「设置 → 对话模式 → 高级」里调整

## 让 AI 参考你的资料

在「设置 → 资料库」导入简历、项目笔记（PDF、Word、Markdown、TXT），或把准备好的问答直接粘贴成文本，AI 作答时会优先参考：

- 经历类问题结合简历里的项目和数据，用第一人称回答；资料里有现成回答的问题，按你准备的要点和说法来
- 每份资料可以分别选择用于截图模式、对话模式；做题模式不使用这份资料库
- 资料只保存在本机，但会随每次请求发给该模式使用的 AI 平台。资料越多回答越慢、费用越高，建议每个模式不超过 3 万字；部分平台支持重复前缀缓存，实际效果与计费以所选平台和模型为准

## 关于隐身能力与隐私的说明

应用使用窗口内容保护机制，实际隐藏效果取决于操作系统和录屏、会议软件，应在当前环境中自行测试。截图、语音和启用的资料会发送到对应服务商；本地 OCR 不需要远程 OCR 服务，但做题分析仍会将截图和相关文字发送给 AI。

本项目仅供学习与研究使用，请遵守使用场合的相关规定。

## 从源码运行与打包

使用 Node.js 22 与 npm，与仓库构建工作流保持一致：

```bash
npm ci
npm run dev
```

本地 OCR 资源位于 `resources/ocr/`，包括 `det.onnx`、`rec.onnx`、`keys.txt` 与校验清单；Windows x64 运行库位于 `resources/ocr-runtime/win32/x64/`。请保留这些资源，打包前会校验其完整性；其他 Windows 架构需要相应的运行库资源。

可在项目根目录创建 `.env`，作为首次配置的默认值：

```env
API_BASE_URL="https://openrouter.ai/api/v1"
API_KEY="your-api-key"
MODEL="your-vision-model"
```

已保存的 AI 配置以应用设置为准。不要将真实 API Key 提交到仓库。

```bash
npm run typecheck   # 类型检查
npm run build       # 检查类型并构建
npm run start       # 预览已构建的应用
npm run build:win   # Windows 安装包
npm run build:mac   # macOS 安装包
```
